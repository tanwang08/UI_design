# UI设计

> 中文改编版：基于 Anthropic 的 frontend-design，已调整名称、语言、Codex 调用方式和交付边界；来源与修改说明见文末。本技能不是 Anthropic 官方中文版。

围绕具体产品和使用者，做有明确意图、可用且有辨识度的界面。配色、字体和布局应当能解释为什么适合当前内容；大胆表达服务于需求，并不意味着每个界面都要抢眼。

## 先理解任务与已有界面

- 从用户需求、当前项目、截图或参考页中确认产品主题、目标用户、首要任务、目标设备，以及要交付方案还是代码。优先使用已有上下文；只有会实质改变方向的信息缺失时才提问，并继续能独立推进的工作。
- 用户明确要求优先。已有产品先看品牌规范、设计 tokens、组件库、页面结构和技术栈；在授权修改范围内改进，保留其他部分的视觉一致性。不能为了追求新颖而擅自更换品牌、字体、组件库或框架。
- 只要求方案、线框或评审时，交付对应结果；要求实现时，完成可运行的界面。不要把设计任务扩大为未经要求的发布、后端开发或整站重构。
- 使用贴合行业与场景的内容。缺少正式内容时，可以写合理的示例文案并标明示例数据，不虚构真实客户评价、认证或经营成绩。

## 形成方向，再落实设计

新设计先用简短说明确定视觉方向；小范围修改则只说明受影响的设计决策，无需重建整套规范。

1. **颜色**：需要新建规范时，通常用 4–6 个有语义名称的十六进制色值描述基础、表面、正文、次要内容和强调色；区分品牌强调与状态语义。已有 tokens 时直接复用并说明必要的变化。
2. **字体**：明确字体及其角色、字号层级、字重、行高与字距。字体选择回应产品气质，并考虑实际可用性、中文覆盖和回退字体。
3. **布局**：用一句话描述信息顺序、对齐方式、密度与视觉重心；当比较结构确实有帮助时，用简短线框图表达。说明窄屏如何重排。
4. **辨识度**：选出最值得记住的一处，让周围内容保持克制。设计主张应能落到具体页面元素，而非停留在“高级、现代、简洁”等形容词。

实现前对照需求审视方案：把产品名字换掉后，这套设计是否仍适用于任何页面？如果是，找出缺少业务依据的选择并调整。设计方案是工作步骤，不是必须等待用户确认的审批关卡；用户明确要求先审方案时按其要求执行。

## 视觉决策

### 首屏与信息层级

让最有代表性的内容先出现。品牌页面可以由标题、图片、演示或交互作为主视觉；工具界面应优先呈现用户要完成的任务，不强塞营销式大首屏。大数字、辅助统计与渐变色只有在传递核心信息时才使用。

边框、分隔线、标签、编号和卡片用于表达内容关系。只有流程、时间线等真实顺序才使用 01 / 02 / 03；不要把无关内容都切成相同圆角、相同阴影的卡片。

### 排版

通常一到两个字体家族就足够；使用两个时，让角色有清晰区别。通过字号、字重、宽度与间距建立层次，标题的排版本身可以承担视觉表达。

长文本保持舒适行宽；英文正文通常控制在每行 80 字符以内，中文按实际字号与阅读密度调整。衬线正文可适当增加行高。不要机械地给标题中的单个词换色或斜体，也不要默认把英文标签全部大写、拉大字距，或为每段内容添加无用的小标题。

### 配色与风格

以下搭配都可能适合特定需求，但不应成为每次自动套用的模板：奶油底色加衬线大标题与陶土色；近黑底色配荧光强调；细线、零圆角的报纸分栏；整齐重复的 SaaS 卡片与装饰性渐变。

同样审视脱离内容的装饰习惯：每个标题上方的全大写标签、无意义的元信息分隔符、小标签一律等宽字体、所有按钮都加箭头。用户或品牌明确要求这些风格时照做；自由选择的部分应根据当前内容决定，而非把“反模板”变成另一套禁用清单。

### 动效

自动播放的动效要少而有目的。一次协调的进入或揭示效果，通常比每个区域都淡入上移、每张卡片都悬浮更清楚。优先用动效解释用户操作后的变化，例如展开、切换与确认；尊重减少动态效果的系统偏好。

## 文案也是界面

- 使用用户能理解的名称，说明对象是什么、动作会发生什么，避免把内部实现术语写进普通用户流程。
- 行动按钮要具体，例如“保存修改”“预约演示”。同一个动作在按钮、处理中提示和结果反馈里使用一致名称。
- 错误说明具体问题及可行的下一步；空状态帮助用户开始行动。避免空泛的报错、反复道歉或只营造情绪的提示。
- 每段文字只做一件事。语言简洁自然、语气匹配品牌；英文通常使用句首大写，不用无信息量的营销口号填补版面。

## 实现与检查

需要实现时，沿用项目现有技术栈、组件与样式组织方式。避免 CSS 选择器互相覆盖，尤其检查区块间距、按钮与通用类的优先级；颜色与间距等重复决策复用现有变量或适量的设计 tokens。

按本次界面的实际功能落实响应式布局、语义结构、键盘操作与可见焦点、可读的对比度，以及相关的加载、空、错误和成功反馈。交互原型中的模拟行为要明确，不能把未接入的功能表述成真实可用。

使用当前环境已有能力检查真实效果：能运行时运行，能查看页面时检查桌面与窄屏截图、关键交互、长文本和溢出。运行与改动相称的项目检查；不要为了简单视觉修改引入整套测试框架。无法运行或截图时说明未验证的部分，不声称已经目视检查。

最后删去不支持信息、操作或品牌表达的装饰。交付时简述结果、关键设计选择和实际验证情况，并给出用户可以查看的页面、文件或预览；不把冗长的自查过程当作成果。
